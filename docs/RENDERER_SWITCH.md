# Переключение DirectX 9 / Vulkan

Реализован `RendererSwitchService`, подключён к WPF-интерфейсу через PatcherBackend.
Payload включён в сборку как Assets/vk09.dll, см. [ASSETS.md](ASSETS.md).

## API

```csharp
var service = new RendererSwitchService();
var result = service.SwitchToVulkan(win32Directory, payloadPath,
    enableHud: true, enableAnisotropy: true);
var reverted = service.SwitchToDirectX(win32Directory);
```

`win32Directory` — разрешённая сервисом поиска папка с GridGame.exe.
`payloadPath` — явный путь к vk09.dll. Библиотека не загружается и не исполняется валидатором.
Результат содержит Renderer, BackupCreated, ExecutableChanged и RecoveryDirectory.
Ошибки передаются вызывающему коду исключениями; UI показывает их в баннере и журнале.

## Проверки и backup

- EXE должен быть x86 PE32, не DLL, с ровно одним импортом d3d9.dll или vk09.dll.
  Проверяются границы таблиц, непрерывность имени и завершающий дескриптор.
  Запасной поиск DLL-строки в произвольном месте EXE не применяется.
- Payload должен быть PE32 x86 DLL с отображаемым в файл экспортом Direct3DCreate9.
  Это проверка структуры и нужного экспорта, а не подписи, версии DXVK или работоспособности DLL.
- GridGame.exe.bak_d3d9 создаётся только при отсутствии. Если EXE уже в Vulkan,
  в копии имя импорта нормализуется в d3d9.dll. Остальные байты текущего EXE сохраняются.
  Поэтому backup — снимок текущего состояния с DirectX, а не гарантия заводского EXE без portable-патчей.
- Существующий backup должен разбираться как PE32 EXE с импортом DirectX.
  Read-Only у такого backup допускается: сервис его не изменяет. Полная идентичность сборки игры не проверяется.
- Изменяемые файлы проверяются на возможность эксклюзивного открытия. Read-Only,
  папки и файловые ссылки в путях назначения приводят к отказу до установки новых файлов.
  Общая транзакция умеет работать с Read-Only только при явном разрешении для записи INI;
  переключение рендера это разрешение не использует.
- Снимок EXE перепроверяется перед записью. Новый backup устанавливается без замены существующего.
  Одновременное изменение игры другими программами не поддерживается; проверки уменьшают риск гонок,
  но не обеспечивают общую блокировку каталога на всю операцию.

## Что изменяется

Vulkan: заменяется только 9-байтный диапазон имени импорта вместе с нулём,
устанавливается vk09.dll и создаётся dxvk.conf по выбранным HUD/анизотропии.
Если оба параметра выключены, dxvk.conf удаляется, как в Python-патчере.
Посторонние ключи dxvk.conf не сохраняются: файл полностью формируется патчером.

DirectX: имя импорта возвращается в d3d9.dll, удаляются vk09.dll, dxvk.conf,
GridGame_d3d9.log. Backup и остальные файлы не изменяются.
EXE не заменяется целиком старым backup: portable-патчи сохраняются.
Повторное применение допускается; совпадающие файлы не перезаписываются.

## Откат при ошибке

1. До изменения файлов в `.tronpatch-<GUID>` внутри папки игры сохраняются исходные байты,
   новые файлы и recovery.txt с соответствием номера и полного пути назначения.
2. Новые файлы устанавливаются через File.Replace или File.Move в том же файловом разделе.
3. При файловой ошибке уже затронутые файлы восстанавливаются в обратном порядке;
   вновь созданные файлы удаляются. Для восстановленных файлов возвращаются атрибуты и LastWriteTimeUtc.
4. Если файл был изменён сторонней программой, откат не перезаписывает его неизвестное содержимое.
5. При ошибке отката выбрасывается PatchTransactionException с RecoveryDirectory и вложенными ошибками.
   Папка с оригиналами сохраняется. `original-N.bin` соответствует строке N в recovery.txt;
   отсутствие такого файла означает, что до операции файла назначения не было.
   Эти копии можно использовать для ручного восстановления после устранения блокировки файлов.
6. После успеха или полного отката служебная папка удаляется. При невозможности очистки после успеха
   её путь возвращается в результате; вызывающий код должен сообщить об оставшейся папке.

Установка атомарна для отдельного файла. Группа операций не является атомарной при завершении процесса,
сбое питания или ОС; автоматическое восстановление после перезапуска пока не реализовано.
Нужны свободное место для снимков и файловая система с поддержкой используемых операций Windows.
Если File.Replace не поддерживается, сервис сообщает ошибку и пытается выполнить откат.

Тесты используют искусственные PE и временные папки. Настоящая библиотека из Python-проекта
проверена только валидатором, без исполнения. Переключение на реальной тестовой копии игры ещё не проверялось.
