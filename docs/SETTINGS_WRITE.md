# Запись GridEngine.ini

Реализована в `GameSettingsService.Apply`, подключена к кнопке «Применить настройки» в WPF.

```csharp
var service = new GameSettingsService();
var settings = service.Read(win32Directory);
settings.ResolutionWidth = 2560;
settings.ResolutionHeight = 1440;
settings.FpsLimit = 165;
settings.SmoothFrameRate = true;
settings.Language = "INT";
var result = service.Apply(settings, win32Directory);
```

Путь выбирается так же, как при чтении: существующий portable-INI или активный редирект
UserData имеют приоритет; иначе используется системная папка «Документы».
`win32Directory` — разрешённая сервисом поиска папка с GridGame.exe, если она известна.

Необязательный `usePortableProfile` позволяет явно выбрать UserData (true) или «Документы» (false).
Без него сохраняется прежний автоматический приоритет. WPF использует явное состояние патча,
чтобы оставшийся portable-INI не перехватывал чтение/запись после отключения редиректа.

## Входные данные

- Ширина, высота и числовой FPS должны быть положительными целыми.
- Для снятия лимита задаётся `SmoothFrameRate=false`; положительное значение FpsLimit
  сохраняется в INI, но не включает сглаживание частоты кадров.
- Язык — три латинские буквы, например RUS, INT, DEU; пробелы по краям удаляются, регистр повышается.
  Исходная модель вызывающего кода не изменяется.
- Ошибочные значения отвергаются до создания папок, изменения содержимого и атрибутов INI.

## Изменение файла

Управляемые ключи: ResX, ResY, MotionBlur, UseVsync в SystemSettings;
Language, bSmoothFrameRate, MaxSmoothedFrameRate в Engine.Engine.

Ключи и секции распознаются без учёта регистра. При повторных секциях и дубликатах
обновляются все вхождения управляемого ключа в его секции. Недостающие ключи вставляются
в последнюю соответствующую секцию; отсутствующая секция добавляется в конец файла.
Одинаковые имена ключей в посторонних секциях сохраняются.

Сохраняются остальные строки, отдельные и встроенные комментарии `;`/`#`, имена ключей,
их отступы и пробелы вокруг `=`, исходные окончания строк и BOM.
У существующих строк сохраняется каждый разделитель; у добавленных используется первый
встреченный в файле либо CRLF для пустого файла. При добавлении после незавершённой строки
вставляется необходимый перевод строки. Если новые строки не нужны, конечный перевод строки не добавляется.
Кавычки в значениях и комментарии после заголовка секции отдельно не интерпретируются.

Поддерживаются UTF-8 с BOM и без него, UTF-16 LE/BE и UTF-32 LE/BE с BOM.
Ошибочные последовательности и нулевые символы в тексте приводят к отказу без записи.
Автоопределение ANSI/Windows-1251 и Unicode без BOM не выполняется.

Если пользовательский INI отсутствует, выдаётся FileNotFoundException с предложением
создать профиль в игре или скопировать существующий. DefaultEngine.ini не копируется,
новые пользовательские INI и каталоги профиля этим сервисом не создаются. Результат
CreatedFromDefault сохранён для совместимости API и всегда равен false.

## Read-Only и ошибки

Используется общая файловая транзакция. Файл с Read-Only разрешён именно для операции настроек;
атрибут снимается непосредственно перед заменой, после успеха выставляется снова.
Остальные исходные атрибуты сохраняются. Повторное применение совпадающих настроек к защищённому
файлу не переписывает его и не меняет LastWriteTimeUtc. Если совпадающий файл был доступен для записи,
ему только добавляется Read-Only.

При файловой ошибке возвращаются исходные байты, атрибуты и время изменения. Время восстанавливается
до возвращения Read-Only, поскольку Windows не разрешает менять его у защищённого файла.
Если откат не завершён, PatchTransactionException сообщает RecoveryDirectory с исходным INI
и recovery.txt; новые непустые папки с этими копиями сохраняются.
При полном откате удаляются только новые пустые папки, созданные этой операцией.

Результат содержит IniPath, CreatedFromDefault, ContentChanged, RecoveryDirectory.
ContentChanged описывает изменение байтов, а не добавление атрибута Read-Only.
Непустой RecoveryDirectory при успехе означает, что очистить служебную папку не удалось;
вызывающий код должен сообщить об этом пользователю.

Как и переключение рендера, операция не гарантирует атомарность при аварийном завершении процесса/ОС
и не поддерживает одновременные изменения файла другими программами. Файловые блокировки
проверяются, неизвестное стороннее содержимое при откате не перезаписывается.
Проверки выполнялись на временных INI и шаблонах; установленная игра не изменялась.
