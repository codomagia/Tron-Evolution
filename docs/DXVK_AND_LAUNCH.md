# Отдельное обновление DXVK и запуск игры

Сервисы подключены к WPF: HUD/анизотропия в Vulkan сохраняются при переключении флажков,
запуск выполняется кнопкой «Запустить игру».

## DXVK

```csharp
var result = new DxvkSettingsService().Update(win32Directory,
    enableHud: true, enableAnisotropy: true);
```

Изменяется только dxvk.conf. GridGame.exe, vk09.dll и backup не открываются,
не копируются и не изменяются. Обновление не переключает рендер и не требует наличия DLL или EXE;
UI должен вызывать его по состоянию выбранной игры, как в исходном патчере.

Конфигурация генерируется так же, как при переключении на Vulkan:

- HUD: `dxvk.hud = fps,devinfo,api`.
- Анизотропия: `d3d9.samplerAnisotropy = 16` и `d3d9.forceSamplerFilter = true`.
- Если оба параметра отключены, файл удаляется.

Посторонние ключи dxvk.conf не сохраняются: полная генерация соответствует Python-патчеру.
Кодировка нового файла — UTF-8 без BOM, окончания строк LF.
Read-Only, ссылка или каталог вместо конфигурации приводят к отказу до изменения.
Несуществующая папка игры не создаётся и вызывает DirectoryNotFoundException.

Применяется общая файловая транзакция с откатом записи/удаления и сохранением исходной
копии при ошибке самого отката. Повторная запись совпадающего файла не меняет его LastWriteTimeUtc.
Новый файл, появившийся после первичной проверки, не должен перезаписываться.

Результат: ConfigurationPath, ConfigurationExists, ContentChanged, RecoveryDirectory.
При ошибке отката PatchTransactionException указывает путь к исходникам.
Общие ограничения транзакции при аварийном завершении процесса и параллельных изменениях сохраняются.

## Запуск

```csharp
var service = new GameLaunchService();
var preview = service.CreateStartInfo(win32Directory); // Только выбор и подготовка.
var result = service.Launch(win32Directory);           // Создание процесса.
```

Порядок выбора первого существующего файла:

1. GridGameLauncherc.exe
2. GridGameLauncher.exe
3. GridGame.exe

Папка с таким именем пропускается. Другие имена файлов не используются.
FileName и WorkingDirectory — абсолютные пути; текущая папка самого патчера не меняется.
Дополнительные аргументы и командная оболочка не используются, повышение прав не запрашивается.
Игра запускается как обычное интерактивное приложение, без скрытия окна.

При отсутствии папки/файлов процесс не создаётся; вызывающий код получает понятное исключение.
Если Windows не смогла запустить выбранный файл, ошибка передаётся вызывающему коду без повторного
запуска через другой лаунчер. Наличие файла не подтверждает исправность игрового EXE.

Результат: ExecutablePath, WorkingDirectory, ProcessId. Получение PID означает создание процесса;
инициализация игры, завершение лаунчера и работа игрового процесса далее не отслеживаются.
Сервис не ожидает выхода игры и не завершает её при освобождении своей ссылки на процесс.

Тесты используют подставной IGameProcessStarter и временные файлы. Реальные игровые процессы
при проверках не запускались; интеграционная проверка на отдельной копии игры ещё впереди.
