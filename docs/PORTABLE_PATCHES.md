# No-Registry, UserData и перенос профиля

Реализован `PortablePatchService`, подключён к portable-параметрам WPF-окна.

```csharp
var service = new PortablePatchService();
var result = service.Apply(win32Directory, noRegistry: true, redirectUserDirectory: true);
var noRegistryOnly = service.SetNoRegistry(win32Directory, enable: false);
var userDataOnly = service.SetUserDirectory(win32Directory, enable: false);
```

Путь к «Документам» по умолчанию получается из SpecialFolder.MyDocuments;
для тестов и явного выбора доступен конструктор с documentsDirectory.
Отдельные методы не меняют второй патч. Apply объединяет оба изменения и перенос профиля в одну транзакцию.

## Проверка EXE

EXE должен быть обычным доступным для записи x86 PE32 с однозначным импортом DirectX/Vulkan.
Существующая резервная копия проверяется и не перезаписывается. При её отсутствии создаётся
GridGame.exe.bak_d3d9 — снимок текущего EXE с импортом DirectX, как при переключении рендера.
Это не подтверждение заводского оригинала и не проверка всего исполняемого кода игры.

No-Registry: по смещению 0x11383E0 допускаются только исходные `81 EC 90 04 00 00`
или включённые `B8 01 00 00 00 C3`. Меняются только эти шесть байт.

UserData: требуется расположение `Binaries/Win32Live/GridGame.exe`, поскольку встроенный код
вычисляет корень игры относительно этого пути. Проверяются:

- ImageBase 0x400000; .text с VirtualSize по смещению 0x240, RVA 0x1000 и RawOffset 0x400.
- Достаточный размер EXE, .text и SizeOfImage, права чтения/исполнения секции и отсутствие перекрытий.
- Согласованное исходное состояние двух вызовов и размера секции либо согласованное включённое состояние.
- Полное совпадение активного cave с 432-байтным кодом из Python-патчера.
  В исходном состоянии допустимы только известный cave после прежнего отключения либо заполнение 00/90/CC.

Неизвестные байты, частичный патч, усечённый файл или неподдерживаемая структура вызывают отказ до записи.
При отключении возвращаются вызовы и VirtualSize; неиспользуемый cave остаётся, как в исходнике.
Импорт рендера и второй portable-патч сохраняются.

Фиксированный машинный код зависит также от поддерживаемой версии игры и её адресов функций.
Проверки заголовков и сигнатур не заменяют проверку на реальной копии игры или полный отпечаток сборки.
Текущие тесты используют искусственный PE с необходимой структурой и не исполняют этот код.

## Копирование профиля

Источник: `<Документы>/Disney Interactive Studios/Tron Evolution`.
Назначение: `<GameRoot>/UserData/Disney Interactive Studios/Tron Evolution`.

- Config (`UnrealEngine3/GridGame/Config`): копируются только файлы верхнего уровня,
  отсутствующие в назначении. Существующие файлы, включая Read-Only, и одноимённые каталоги пропускаются.
  Вложенные папки конфигов не копируются, как в Python.
- SaveData: дерево целиком, включая пустые каталоги, копируется только в пустое назначение.
  Если в SaveData уже есть хотя бы один файл или каталог, всё исходное дерево сохранений пропускается.
  Это предотвращает смешивание профилей; отсутствующие файлы внутрь существующего профиля не добавляются.
- Низкоуровневый PortablePatchService может подготовить пустые каталоги, но интерфейс теперь проверяет профиль до вызова этого сервиса: без пользовательского INI и сохранения CHECKPT применение настроек блокируется. Перенос между расположениями выполняется отдельной кнопкой; см. [GAME_PROFILES.md](GAME_PROFILES.md).
- Исходные файлы не удаляются и не изменяются. Для новых копий сохраняются LastWriteTimeUtc
  и поддерживаемые атрибуты ReadOnly, Hidden, System, Archive, NotContentIndexed.
  ACL, альтернативные потоки NTFS, шифрование и сжатие не переносятся.
- Исходные файлы читаются с эксклюзивным доступом. Ошибки чтения останавливают операцию до установки файлов.
- Ссылки в обрабатываемых файлах/цепочках каталогов и рекурсивном дереве исходных сейвов не обходятся;
  при их обнаружении операция отвергается. Нетронутые непустые portable-сейвы не обходятся.
- Корни источника и назначения не должны совпадать или находиться друг внутри друга.

Повторное применение допустимо. Недостающие конфиги могут быть добавлены при следующем вызове;
занятый SaveData остаётся нетронутым. При отключении UserData portable-конфиги и прогресс сохраняются
внутри игры и обратно в «Документы» автоматически не копируются.

## Операция и восстановление

Сначала проверяется EXE и подготавливаются новые байты и копии профиля; затем создаются
недостающие каталоги назначения. Общая файловая транзакция готовит снимки и устанавливает:
backup при его отсутствии, новые файлы профиля, затем EXE. Новый файл никогда не заменяет существующий.

При ошибке восстанавливается EXE, удаляются только файлы, созданные этой операцией,
и новые пустые папки. Read-Only у новых копий снимается перед удалением при откате.
Исходные документы и ранее существовавшие portable-файлы не участвуют в записи.
Если сам откат не завершён, PatchTransactionException сообщает RecoveryDirectory с исходниками и manifest recovery.txt.
Папки с исходными копиями не удаляются. Стороннее неизвестное содержимое при откате не перезаписывается.

Результат содержит состояния обоих патчей, ExecutableChanged, BackupCreated, счётчики
CopiedConfigurationFiles/SkippedConfigurationFiles/CopiedSaveFiles, признак SaveDataAlreadyPresent
и RecoveryDirectory. Непустой RecoveryDirectory при успехе означает, что служебную папку не удалось очистить.

Как и другие операции записи, группа файлов не атомарна при аварийном завершении процесса/ОС.
Автовосстановление после перезапуска и одновременные изменения файлов игры другими программами не поддерживаются.
Изменение реестра Windows не выполняется: No-Registry меняет проверку внутри EXE.
